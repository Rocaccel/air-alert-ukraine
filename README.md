# ESP Alert — устройство для индикации тревоги по региону Украины

Мониторинг воздушных тревог на ESP32-S + MicroPython: плата опрашивает открытые
API, при тревоге в выбранном регионе мигает внешним LED, состояние и настройки
отдаются через веб-панель. Версия 0.4.0 — пре-релиз, не 1.0:
API и поведение ещё могут меняться.

## Ключевые фичи

- 155 регионов с поиском: области, м. Київ/Харків/Запоріжжя/Одеса, все районы + 11 громад;
- Авто-failover: области ubilling → tryvoha, юниты aiu raw → ual raw → область;
- Веб-панель с вкладками: регион, WiFi, обновление прошивки;
- Восстановление без панели: кнопка FLASH (GPIO0) при старте → откат из `/bak`;
- OTA-бандлы `.tar.gz`, собранные `pack.py`
- Ноль записей во flash в дежурном цикле (конфиг пишется только по Save);
- Сторож веб-потока, кольцевой лог в RAM, `/status` в JSON.

## Tech stack

- **Плата**: ESP32-S (проверено на NodeMCU-32S), LED на GPIO2;
- **Прошивка**: MicroPython 1.28 (ESP32_GENERIC, `_mpy=11014`);
- **Язык**: MicroPython (CPython-совместимый Python 3.4+ синтаксис, без `async`);
- **Сеть**: только plain HTTP (на ESP нет TLS) — `usocket`, свой HTTP-клиент и сервер;
- **Распакровка OTA**: `deflate.DeflateIO` (1.28) / `uzlib` / `zlib` + вендоренный
  `utarfile.py` из micropython-lib (MIT);
- **Потоки**: `_thread`, вторичный поток со стеком 6КБ;
- **Заливка**: `mpremote` по USB (основной путь), OTA-бандл по LAN (запасной).

## Структура проекта

```text
esp-alert/
├── src/                  # прошивка (11 файлов, все едут на ESP)
│   ├── boot.py           # WiFi STA 15с -> fallback AP, вспышки LED, кнопка FLASH -> откат
│   ├── main.py           # главный цикл: опрос API, сторож потока, WiFi-монитор
│   ├── alerts.py         # API-источники, REGIONS (155), PARENT-карта районов
│   ├── web.py            # HTTP-сервер, роуты, чанковый рендер шаблона
│   ├── template.html     # RU-панель (~14КБ, 18 токенов {{...}})
│   ├── ota.py            # скачивание, распаковка .tar.gz, откат из /bak
│   ├── utarfile.py       # вендоренный tar-ридер (micropython-lib, MIT)
│   ├── config_store.py   # config.json + санитизация
│   ├── version.py        # FW_VERSION (сейчас 0.4.0)
│   ├── hw.py             # LED_PIN = 2
│   └── logbuf.py         # кольцевой лог 25 строк в RAM
├── config_default.json   # дефолты (дублируют DEFAULTS в коде)
├── pack.py / pack.bat    # сборка firmware.tar.gz (gzip wbits=9!)
├── upload.bat            # заливка отдельных файлов по USB (mpremote, COM3)
└── build-mpy.bat         # предкомпиляция .py → .mpy (нужен mpy-cross; web.mpy/alerts.mpy едут на плату вместо .py)
```

На устройстве дополнительно создаются: `config.json` (только по Save),
`/bak/*.py` (копии перед OTA-перезаписью), `tmp_bundle.tar.gz` (временный).

## Prerequisites

- MicroPython 1.28.x, прошитый в ESP32-S (Thonny → Tools → Options → Interpreter);
- Python 3 на ПК + `mpremote` (`python -m pip install mpremote`);
- USB-кабель данных (плата видна как COM-порт, обычно CP210x);
- Для OTA: плата и ПК в одной LAN (тумблер убран в 0.2.1, роуты всегда открыты).

## Первый запуск

1. Прошей MicroPython 1.28 (раздел Interpreter в Thonny).
2. Залей в корень ESP файлы из `src/` (Thonny или
   `upload.bat boot.py main.py config_store.py ota.py version.py hw.py logbuf.py template.html utarfile.py web.mpy alerts.mpy`) —
   **11 файлов: `web.py` и `alerts.py` НЕ заливаются, только `web.mpy`
   и `alerts.mpy`**. Причина: у `.py` приоритет над `.mpy` — если оба
   лежат, устройство компилирует `.py` само; компиляция `web.py`+`alerts.py`
   (66КБ подряд после WiFi-инициализации) аллокационным пиком рвёт кучу,
   lwIP остаётся без буферов — плата перестаёт отвечать на ping/DNS при
   живом WiFi. `.mpy` собираются автоматически `pack.py`/`pack.bat`
   (нужен mpy-cross 1.28.x) или `build-mpy.bat`.
3. Если на плате нет WiFi-настроек — поднимется открытая AP `ESP32-ALERT`,
   страница `http://192.168.4.1/` (1 вспышка LED = STA ok, 2 = AP-режим).
4. Открой страницу, введи SSID/пароль роутера, выбери регион, Save —
   плата перезагрузится и выйдет в STA (IP покажет роутер или REPL `STA IP: ...`).
5. Проверка: `http://<STA-IP>/status` → `{"fw": "0.4.0", "alert": false, ...}`.

## Архитектура

### Потоки

- **Главный таск**: опрос API каждые `check_interval`, WiFi-монитор,
  сторож вторичного потока (перезапуск при протухшем heartbeat).
- **Вторичный поток** (стек 6КБ): неблокирующий веб-сервер (`poll` без
  ожидания), мигание LED при `alert`, heartbeat `worker_ts` в `state`.
- Замок `_thread.allocate_lock()` вокруг `state`; если потоков нет —
  синхронный fallback-режим в том же файле.

### Жизненный цикл запроса

```text
poll() -> accept -> чтение заголовков -> роут по path+method ->
/save: разбор формы, config_store.save(), рендер с msg
/ota-bundle: стрим multipart в файл -> unpack_tar_gz -> msg
остальное: маленькие ответы собирается целиком (байты, не килобайты)
```

### Стриминги (почему нет OOM при 62КБ free)

Куча фрагментирована: нет непрерывных 13+КБ. Поэтому всё большое —
только потоком, пик ~1КБ:

- **Рендер страницы**: 2 прохода по `template.html` чанками 512Б
  (замер длины -> отправка), токен на границе чанков не теряется
  (overlap + откат partial-токена). `{{REGION_OPTIONS}}` (155 опций)
  шлётся поштучно, общей строки нет. `Content-Length` точный.
- **Приём бандла**: тело multipart пишется сразу в `tmp_bundle.tar.gz`,
  holdback ~100Б отрезает концевую границу.
- **Распаковка**: `deflate.DeflateIO(f, GZIP, 9)` — окно 512Б.
  Бандл собирается `pack.py` (gzip wbits=9); обычный `tar -czf`
  (wbits=15, окно 32КБ) устройство не примет — будет честная ошибка.

### Источники тревоги (`alerts.py`)

```text
область:  ubilling (прямо) -> tryvoha (запасной)
юнит:     aiu raw -> ual raw -> область по ubilling (тег ubilling~oblast)
          имена цепочки «юнит -> район -> область» в одном потоковом проходе
```

- **ubilling** `http://ubilling.net.ua/aerialalerts/` — ~4КБ, только области.
  `alertnow` поднимается и от тревог в отдельных районах — для юнитов это
  осознанно грубый последний fallback.
- **aiu raw** `...?source=aiu&raw` — alerts.in.ua raw (до ~64КБ): активная
  тревога = `location_title` из набора цепочки + `finished_at` не задан
  (`null`); `alert_type` не проверяется — активен любой тип. Записи часто
  дублируются по типу — это норма.
- **ual raw** `...?source=ual&raw` — ukrainealarm raw: `regionName` из набора
  + непустой `activeAlerts`.
- **Сканер `_RawScan`** — байтовая машина состояний: тело в RAM не копится
  (`SCAN_BODY_LIMIT` 256КБ), соединение обрывается на первом совпадении,
  декодирует `\uXXXX` (ubilling экранирует кириллицу). Имена цепочки —
  в одном наборе: тайтл любого звена (громада/город/район/область) активен —
  регион активен. `ALIASES` покрывает расхождения имён между источниками
  (aiu — короткие, ual — «м. X та ...», label в `REGIONS` — для веба).
- **tryvoha** `http://tryvoha.online/api/v1/alerts/{slug}` — с 2026-09
  отдаёт `301 → https` (Cloudflare). На ESP нет TLS, поэтому прямое
  обращение сейчас всегда падает — запасной источник только для областей;
  юниты в него не ходят.
- **Fallback юнитов**: словарь `PARENT` (130 записей: юнит → район →
  область, сверено с aiu `location_raion` и справочником alerts.in.ua).
  При отказе обоих raw-источников юнит показывает тревогу своей области.
  Точность осознанно ниже, тег источника на странице честный.
- ubilling держит лимит ~2 rps: между сырьевыми запросами пауза 700мс.
- При отказе всего LED держит последнее состояние, `last_err` на странице.

## Конфиг (`config.json`, только по Save)

| Ключ | Тип | Дефолт | Описание |
| ---- | --- | ------ | -------- |
| `region` | slug | `odeska` | Регион из 155 (валидируется, чужой → дефолт) |
| `check_interval` | 10–3600 | `60` | Период опроса API, сек |
| `wifi_ssid` / `wifi_pass` | строки | `""` | STA-подключение; смена → авторебут |
| `blink_on_ms` / `blink_off_ms` | мс | `500` | Мигание (только правкой файла, в панели нет) |

Санитизация при каждом чтении: неизвестные ключи отбрасываются,
интервал климпится, регион проверяется по `REGIONS`.

## Веб-панель и роуты

Панель: статус-карта + 3 вкладки на чистом CSS (radio; есть только маленький
скрипт — синхронизация выбранного региона со скрытым полем slug):
«Регион и проверка», «Настройки WiFi», «Обновление прошивки»
(там же опасная зона: ребут). Футер показывает режим сети
и реальный IP-адрес ссылкой (`{{NETMODE}}` / `{{IPURL}}`).

| Метод + путь | Что делает |
| ------------ | ---------- |
| `GET /` | Панель (стрим-рендер, 18 токенов) |
| `GET /status` | JSON: `fw/alert/region/source/last_err/ip/log_tail` |
| `POST /save` | Форма настроек → `config.json`, ребут при смене WiFi |
| `POST /reboot` | `machine.reset()` |
| `POST /ota-bundle` | multipart `.tar.gz` → распаковка → `Пакет OK` + ручной ребут |
| `POST /ota-url` | Скачать файл/бандл по публичному URL самому ESP (форма из панели убрана, вызов только ручным POST) |
| `POST /upload` | Отключён: одиночная заливка только через USB |

## Скрипты

| Скрипт | Назначение |
| ------ | ---------- |
| `upload.bat f1 f2...` | **Основной путь**: файлы из `src/` по USB (mpremote, COM3) + reset |
| `pack.bat` / `pack.py` | Сборка `firmware.tar.gz`: tar + gzip **wbits=9**, авто-компиляция `web.mpy`/`alerts.mpy` (mpy-cross) |
| `build-mpy.bat` | `.py` → `.mpy` отдельно от бандла (нужен mpy-cross 1.28.x) |

Правила для `.bat`: CRLF-переводы строк (LF ломает `goto`/`if`),
без скобок в REM-строках.

## Обновление прошивки

- **USB (основной)**: `upload.bat web.mpy version.py` — только изменённые
  файлы + reset. Проверка: `/status` → `fw`. Требует свободного COM-порта
  (отпустить в Thonny). `web.py`/`alerts.py` на устройство не кладутся:
  правка этих файлов = перекомпиляция одноимённого `.mpy`
  (`pack.py` или `build-mpy.bat`) и заливка `.mpy` (иначе либо
  молча не применится, либо — при наличии `.py` — вернётся
  on-device компиляция со всеми рисками памяти).
- **OTA (запасной)**: `pack.bat` → форма «Полный архив» → `Пакет OK` →
  ребут кнопкой. Перед записью старые файлы копируются в `/bak` потоково
  по 1 КБ (цельное чтение падало на фрагментированной куче у `alerts.py`
  и `web.py` — бэкап молча не создавался). Если бэкап не удался, файл в
  `/bak` не остаётся полузаписанным, а в ответе OTA видно
  `бэкап не удался: …`; `config.json` не затирается никогда.
- **Откат (без панели)**: удержать кнопку **FLASH** (GPIO0) в течение ~2с
  после нажатия **RST** — `boot.py` восстанавливает файлы из `/bak`
  и перезагружается. Ответ LED: 5 вспышек = откат выполнен,
  10 = ошибка или `bak` пуст (затем обычная загрузка). Панель не нужна —
  срабатывает и при сломанных main/web/шаблоне, пока жив REPL.
  Держать FLASH при обычном включении (power-on) нельзя — чип уйдёт
  в режим прошивки (download mode). Запасной путь с ПК: `upload.bat`
  известных-хороших файлов, либо
  `mpremote connect COM3 exec "import ota; ota.rollback()"` + `... reset`.
  Запись идёт через стейджинг `x.rbt` + rename — корневой файл не остаётся
  обрезанным, сбойные файлы видны в логе `button rollback: … | fail: …`.
- **Настройки**: `config.json` пишется только по «Сохранить» и атомарно
  (`config.json.tmp` → rename): при обрыве питания остаётся либо старый,
  либо новый файл, но не полусохранённый.

## Тестирование

Тестового раннера в репозитории нет — проверки гоняются на ПК
портируемым Python со стабами MicroPython:

- `python -m py_compile src/*.py` — синтаксис;
- стабы `const` (builtin), `uctypes` (мини-эмуляция struct/ARRAY),
  `uzlib`/`deflate` (через `gzip`), `machine` (пустышка) — затем импорт
  **настоящих** `ota.py` / `web.py` / `alerts.py` / `utarfile.py`;
- что покрывалось: round-trip бандла (ALLOWED-фильтр, бэкап, `config.json`
  жив), потоковый `backup`/`rollback` (sha-копии, удаление полузаписанного
  файла, staging `.rbt`), атомарность `save()` (упавший `rename` → старый
  конфиг цел), побайтовая эквивалентность стрим-рендера при чанках 7–5000,
  стрим-приём multipart 30КБ, полнота `PARENT` 130/130 + сверка имён
  цепочек со справочником alerts.in.ua, потоковый сканер `_RawScan`
  (реальные выгрузки aiu/ual, разрезы чанков 1..4096, `\uXXXX`,
  негативы «чужой район → False», битый JSON → исключение) и
  сценарии `check()` со стабами источников.

## Диагностика

| Симптом | Причина → лечение |
| ------- | ----------------- |
| `memory allocation failed, allocating 12965` на `/` | Старый рендер целой страницей → обновиться (стриминг) |
| `ERR: ...301 Moved Permanently` | tryvoha (запасной только для областей) требует https → норма; юниты идут через aiu/ual, последний рубеж — `ubilling~oblast` |
| `Ошибка приема: memory allocation failed` | Старый приём бандла в RAM → обновиться (стрим в файл) |
| `Ошибка пакета: need uzlib/zlib` | Прошивка без `deflate` → обновиться (ветка `deflate`) |
| `Ошибка пакета: ...32768` | Бандл собран не `pack.py` (wbits=15) → пересобрать `pack.bat` |
| `бэкап не удался: x` в ответе OTA | Нет места/ошибка flash при копировании в `/bak` → освободить flash, повторить обновление |
| Панель не грузится, нужен откат | RST → зажать FLASH ~2с до вспышек (5 = ок, 10 = ошибка/`bak` пуст) |
| Кнопка FLASH не сработала | Отпустили раньше ~400мс удержания или вне окна ~2с → повторить (RST, сразу зажать) |
| Параметры съехали в дефолты после Save | Обрыв питания при записи конфига (старые версии писали неатомарно) → обновиться |
| `failed to access COM3` | Порт держит Thonny → Stop/закрыть |
| `.bat` выполняет куски комментариев | LF-переводы или скобки в REM → CRLF, без скобок |
| `/status` молчит, пинг есть | Веб-поток лёг → ребут; смотри REPL-лог через USB |
| Нет ping/DNS при живом WiFi после заливки `.py` | У `.py` приоритет: устройство компилирует `web.py`/`alerts.py` на старте → пик рвёт кучу → убрать `.py` с устройства (залить `.mpy`), ребут |
| Обновление `.py` отклоняет `.mpy` | У `.py` приоритет над `.mpy`: не класть `web.py`/`alerts.py` на плату — обновлять `.mpy` (`pack.py`, `build-mpy.bat`) |

## Железо

- NodeMCU-32S: встроенный синий LED на GPIO2 + внешний параллельно
  (анод → GPIO2, катод → 220–330 Ом → GND). Пин зашит в `hw.py`.
- В простое погашен, при `alert` мигает 500/500 мс.
- При старте: 1 вспышка = STA ok, 2 = AP-режим. Не роняет загрузку.
- Кнопки NodeMCU-32S: **RST** — перезагрузка; **FLASH** (GPIO0) — зажата
  ≥400мс в окне ~2с после старта → откат из `/bak` (5 вспышек = ок,
  10 = ошибка/`bak` пуст), затем авто-перезагрузка. Обычное включение
  с зажатой FLASH — режим прошивки (download mode), так не делать.
