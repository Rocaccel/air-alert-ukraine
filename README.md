# ESP Alert — устройство для индикации тревоги по региону Украины

Мониторинг воздушных тревог на ESP32-S + MicroPython: плата опрашивает открытые
API, при тревоге в выбранном регионе мигает внешним LED, состояние и настройки
отдаются через веб-панель. Версия 0.1.8 — пре-релиз, не 1.0:
API и поведение ещё могут меняться.

## Ключевые фичи

- 145 регионов с поиском: области, м. Київ/Харків/Запоріжжя, все районы + 2 громады;
- Авто-failover источников: ubilling → tryvoha → тревога родительской области;
- Веб-панель с вкладками: регион, WiFi, OTA-обновление, откат из `/bak`;
- OTA-бандлы `.tar.gz`, собранные `pack.py`
- Ноль записей во flash в дежурном цикле (конфиг пишется только по Save);
- Сторож веб-потока, кольцевой лог в RAM, `/status` в JSON.

## Tech stack

- **Плата**: ESP32-S (проверено на NodeMCU-32S), LED на GPIO2;
- **Прошивка**: MicroPython 1.28 (ESP32_GENERIC, `_mpy=11014`);
- **Язык**: MicroPython (CPython-совместимый Python 3.4+ синтаксис, без `async`);
- **Сеть**: только plain HTTP (на ESP нет TLS) — `usocket`, свой HTTP-клиент и сервер;
- **Распакровка OTA**: `deflate.DeflateIO` (1.28) / `uzlib` / `zlib` + вендоренный
  `utarfile.py` из micropython-lib (MIT);
- **Потоки**: `_thread`, вторичный поток со стеком 6КБ;
- **Заливка**: `mpremote` по USB (основной путь), OTA-бандл по LAN (запасной).

## Структура проекта

```text
esp-alert/
├── src/                  # прошивка (11 файлов, все едут на ESP)
│   ├── boot.py           # WiFi STA 15с -> fallback AP, вспышки LED
│   ├── main.py           # главный цикл: опрос API, сторож потока, WiFi-монитор
│   ├── alerts.py         # API-источники, REGIONS (145), PARENT-карта районов
│   ├── web.py            # HTTP-сервер, роуты, чанковый рендер шаблона
│   ├── template.html     # RU-панель (~14КБ, 19 токенов {{...}})
│   ├── ota.py            # скачивание, распаковка .tar.gz, откат из /bak
│   ├── utarfile.py       # вендоренный tar-ридер (micropython-lib, MIT)
│   ├── config_store.py   # config.json + санитизация
│   ├── version.py        # FW_VERSION (сейчас 0.1.8)
│   ├── hw.py             # LED_PIN = 2
│   └── logbuf.py         # кольцевой лог 25 строк в RAM
├── config_default.json   # дефолты (дублируют DEFAULTS в коде)
├── pack.py / pack.bat    # сборка firmware.tar.gz (gzip wbits=9!)
├── upload.bat            # заливка отдельных файлов по USB (mpremote, COM3)
└── build-mpy.bat         # опциональная предкомпиляция в .mpy (нужен mpy-cross)
```

На устройстве дополнительно создаются: `config.json` (только по Save),
`/bak/*.py` (копии перед OTA-перезаписью), `tmp_bundle.tar.gz` (временный).

## Prerequisites

- MicroPython 1.28.x, прошитый в ESP32-S (Thonny → Tools → Options → Interpreter);
- Python 3 на ПК + `mpremote` (`python -m pip install mpremote`);
- USB-кабель данных (плата видна как COM-порт, обычно CP210x);
- Для OTA: плата и ПК в одной LAN, включённый тумблер OTA на странице.

## Первый запуск

1. Прошей MicroPython 1.28 (раздел Interpreter в Thonny).
2. Залей все 11 файлов из `src/` в корень ESP (Thonny или `upload.bat boot.py main.py config_store.py alerts.py web.py ota.py version.py hw.py logbuf.py template.html utarfile.py`).
3. Если на плате нет WiFi-настроек — поднимется открытая AP `ESP32-ALERT`,
   страница `http://192.168.4.1/` (1 вспышка LED = STA ok, 2 = AP-режим).
4. Открой страницу, введи SSID/пароль роутера, выбери регион, Save —
   плата перезагрузится и выйдет в STA (IP покажет роутер или REPL `STA IP: ...`).
5. Проверка: `http://<STA-IP>/status` → `{"fw": "0.1.8", "alert": false, ...}`.

## Архитектура

### Потоки

- **Главный таск**: опрос API каждые `check_interval`, WiFi-монитор,
  сторож вторичного потока (перезапуск при протухшем heartbeat).
- **Вторичный поток** (стек 6КБ): неблокирующий веб-сервер (`poll` без
  ожидания), мигание LED при `alert`, heartbeat `worker_ts` в `state`.
- Замок `_thread.allocate_lock()` вокруг `state`; если потоков нет —
  синхронный fallback-режим в том же файле.

### Жизненный цикл запроса

```text
poll() -> accept -> чтение заголовков -> роут по path+method ->
/save: разбор формы, config_store.save(), рендер с msg
/ota-bundle: стрим multipart в файл -> unpack_tar_gz -> msg
остальное: маленькие ответы собирается целиком (байты, не килобайты)
```

### Стриминги (почему нет OOM при 62КБ free)

Куча фрагментирована: нет непрерывных 13+КБ. Поэтому всё большое —
только потоком, пик ~1КБ:

- **Рендер страницы**: 2 прохода по `template.html` чанками 512Б
  (замер длины -> отправка), токен на границе чанков не теряется
  (overlap + откат partial-токена). `{{REGION_OPTIONS}}` (145 опций)
  шлётся поштучно, общей строки нет. `Content-Length` точный.
- **Приём бандла**: тело multipart пишется сразу в `tmp_bundle.tar.gz`,
  holdback ~100Б отрезает концевую границу.
- **Распаковка**: `deflate.DeflateIO(f, GZIP, 9)` — окно 512Б.
  Бандл собирается `pack.py` (gzip wbits=9); обычный `tar -czf`
  (wbits=15, окно 32КБ) устройство не примет — будет честная ошибка.

### Источники тревоги (`alerts.py`)

```text
область:  ubilling (прямо) -> tryvoha (запасной)
район:    tryvoha (точно) -> тревога области (приближение, тег ubilling~oblast)
```

- **ubilling** `http://ubilling.net.ua/aerialalerts/` — ~4КБ, только области.
  Работает по plain HTTP, проверено.
- **tryvoha** `http://tryvoha.online/api/v1/alerts/{slug}` — с 2026-09
  отдаёт `301 → https` (Cloudflare). На ESP нет TLS, поэтому прямое
  обращение сейчас всегда падает — для районов это первая попытка,
  для областей запасная.
- **Fallback районов**: словарь `PARENT` (120 записей: район → область,
  часть сверена с живым tryvoha). Район показывает тревогу своей области.
  Точность осознанно ниже: возможны лишние срабатывания и пропуски чисто
  локальных тревог. Тег источника на странице честный.
- При отказе всего LED держит последнее состояние, `last_err` на странице.

## Конфиг (`config.json`, только по Save)

| Ключ | Тип | Дефолт | Описание |
| ---- | --- | ------ | -------- |
| `region` | slug | `odeska` | Регион из 145 (валидируется, чужой → дефолт) |
| `check_interval` | 10–3600 | `60` | Период опроса API, сек |
| `wifi_ssid` / `wifi_pass` | строки | `""` | STA-подключение; смена → авторебут |
| `ota_enabled` | bool | `true` | Разрешить OTA и откат |
| `blink_on_ms` / `blink_off_ms` | мс | `500` | Мигание (только правкой файла, в панели нет) |

Санитизация при каждом чтении: неизвестные ключи отбрасываются,
интервал климпится, регион проверяется по `REGIONS`.

## Веб-панель и роуты

Панель: статус-карта + 3 вкладки на чистом CSS (radio, без JS):
«Регион и проверка», «Настройки WiFi», «Автоматическое обновление»
(там же опасная зона: откат, ребут). Футер показывает режим сети
и реальный IP (`{{NETMODE}}` / `{{IPURL}}`).

| Метод + путь | Что делает |
| ------------ | ---------- |
| `GET /` | Панель (стрим-рендер, 19 токенов) |
| `GET /status` | JSON: `fw/alert/region/source/last_err/ip/log_tail` |
| `POST /save` | Форма настроек → `config.json`, ребут при смене WiFi |
| `POST /reboot` | `machine.reset()` |
| `POST /ota-bundle` | multipart `.tar.gz` → распаковка → `Пакет OK` + ручной ребут |
| `POST /ota-url` | Скачать файл/бандл по публичному URL самому ESP |
| `POST /ota-rollback` | Откат записанных файлов из `/bak` |
| `POST /upload` | Отключён (v5): одиночная заливка только через USB |

## Скрипты

| Скрипт | Назначение |
| ------ | ---------- |
| `upload.bat f1 f2...` | **Основной путь**: файлы из `src/` по USB (mpremote, COM3) + reset |
| `pack.bat` / `pack.py` | Сборка `firmware.tar.gz`: tar + gzip **wbits=9** |
| `build-mpy.bat` | Опционально: `.py` → `.mpy` (нужен mpy-cross 1.28.x) |

Правила для `.bat`: CRLF-переводы строк (LF ломает `goto`/`if`),
без скобок в REM-строках.

## Обновление прошивки

- **USB (основной)**: `upload.bat web.py version.py` — только изменённые
  файлы + reset. Проверка: `/status` → `fw`. Требует свободного COM-порта
  (отпустить в Thonny).
- **OTA (запасной)**: `pack.bat` → форма «Полный архив» → `Пакет OK` →
  ребут кнопкой. Перед записью старые файлы копируются в `/bak`,
  `config.json` не затирается никогда.
- **Откат**: форма «Откат из /bak» (только при включённом OTA).

## Тестирование

Тестового раннера в репозитории нет — проверки гоняются на ПК
портируемым Python со стабами MicroPython:

- `python -m py_compile src/*.py` — синтаксис;
- стабы `const` (builtin), `uctypes` (мини-эмуляция struct/ARRAY),
  `uzlib`/`deflate` (через `gzip`), `machine` (пустышка) — затем импорт
  **настоящих** `ota.py` / `web.py` / `alerts.py` / `utarfile.py`;
- что покрывалось: round-trip бандла (ALLOWED-фильтр, бэкап, `config.json`
  жив), побайтовая эквивалентность стрим-рендера при чанках 7–5000,
  стрим-приём multipart 30КБ, полнота `PARENT` 120/120 + сверка с живым
  tryvoha, 5 сценариев `check()`.

## Диагностика

| Симптом | Причина → лечение |
| ------- | ----------------- |
| `memory allocation failed, allocating 12965` на `/` | Старый рендер целой страницей → обновиться (стриминг с 2.1.2) |
| `ERR: ...301 Moved Permanently` у районов | tryvoha требует https → норма, работает fallback `ubilling~oblast` |
| `Ошибка приема: memory allocation failed` | Старый приём бандла в RAM → обновиться (стрим в файл с 2.1.5) |
| `Ошибка пакета: need uzlib/zlib` | Прошивка без uzlib → обновиться (ветка `deflate` с 2.1.6) |
| `Ошибка пакета: ...32768` | Бандл собран не `pack.py` (wbits=15) → пересобрать `pack.bat` |
| `failed to access COM3` | Порт держит Thonny → Stop/закрыть |
| `.bat` выполняет куски комментариев | LF-переводы или скобки в REM → CRLF, без скобок |
| `/status` молчит, пинг есть | Веб-поток лёг → ребут; смотри REPL-лог через USB |

## Железо

- NodeMCU-32S: встроенный синий LED на GPIO2 + внешний параллельно
  (анод → GPIO2, катод → 220–330 Ом → GND). Пин зашит в `hw.py`.
- В простое погашен, при `alert` мигает 500/500 мс.
- При старте: 1 вспышка = STA ok, 2 = AP-режим. Не роняет загрузку.
