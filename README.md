Плата опрашивает открытые API тревог и при тревоге в выбранном регионе мигает
внешним LED. Состояние и настройки — через веб-панель. Версия 0.4.0 — пре-релиз:
API и поведение ещё могут меняться.

> [!NOTE]
> Работает только на plain HTTP: у ESP32 нет TLS. Проверено на NodeMCU-32S
> с прошивкой MicroPython 1.28 (`_mpy=11014`).

## Возможности

- 155 регионов с поиском: области, м. Київ/Харків/Запоріжжя/Одеса, все районы + 11 громад
- Авто-failover: области ubilling → tryvoha, юниты aiu raw → ual raw → область
- Веб-панель с вкладками: регион, WiFi, обновление прошивки
- Восстановление без панели: кнопка FLASH при старте → откат из `/bak`
- OTA-бандлы `.tar.gz`, сборка и релиз одной командой
- Ноль записей во flash в дежурном цикле (конфиг пишется только по Save)
- Сторож веб-потока, кольцевой лог в RAM, `/status` в JSON

## Быстрый старт

### Требования

- MicroPython 1.28.x, прошитый в ESP32-S (Thonny → Tools → Options → Interpreter)
- Python 3 на ПК + `mpremote` (`python -m pip install mpremote`)
- USB-кабель данных (плата видна как COM-порт, обычно CP210x)
- Для OTA: плата и ПК в одной LAN (роуты всегда открыты)
- Для релизов: GitHub CLI `gh` с авторизацией

### Первый запуск

1. Прошей MicroPython 1.28 (раздел Interpreter в Thonny).
2. Залей в корень ESP файлы из `src/`:
   ```text
   upload.bat boot.py main.py config_store.py ota.py version.py hw.py
             logbuf.py template.html utarfile.py web.mpy alerts.mpy
   ```
3. Если на плате нет WiFi-настроек — поднимется открытая AP `ESP32-ALERT`,
   страница `http://192.168.4.1/`.
4. Введи SSID/пароль роутера, выбери регион, Save — плата перезагрузится
   и выйдет в STA.
5. Проверка: `http://<STA-IP>/status` → `{"fw": "0.4.0", "alert": false, ...}`.

> [!WARNING]
> **`web.py` и `alerts.py` на устройство не заливаются — только
> `web.mpy`/`alerts.mpy`.** У `.py` приоритет над `.mpy`: если оба лежат на
> плате, устройство компилирует `.py` само, а компиляция 66КБ после
> WiFi-инициализации аллокационным пиком рвёт кучу → lwIP без буферов →
> нет ping/DNS при живом WiFi. Правка этих файлов = перекомпиляция `.mpy`
> (`pack.py` или `build-mpy.bat`) и заливка `.mpy`.

Ответ LED при старте: 1 вспышка = STA ok, 2 = AP-режим.

## Архитектура

### Потоки

- **Главный таск**: опрос API каждые `check_interval`, WiFi-монитор,
  сторож вторичного потока (перезапуск при протухшем heartbeat).
- **Вторичный поток** (стек 6КБ): неблокирующий веб-сервер (`poll` без
  ожидания), мигание LED при `alert`, heartbeat в `state`.
- Замок вокруг `state`; если потоков нет — синхронный fallback в том же файле.

### Стриминги

Куча фрагментирована: нет непрерывных 13+КБ. Всё большое идёт потоком,
пик аллокаций ~1КБ:

- **Рендер страницы**: 2 прохода по `template.html` чанками 512Б (замер
  длины → отправка), токен на границе чанков не теряется. 155 опций
  `{{REGION_OPTIONS}}` шлются поштучно. `Content-Length` точный.
- **Приём бандла**: тело multipart сразу в `tmp_bundle.tar.gz`,
  holdback ~100Б отрезает концевую границу.
- **Распаковка**: `deflate.DeflateIO(f, GZIP, 9)` — окно 512Б.

> [!TIP]
> Бандл собирается `pack.py` с gzip **wbits=9**. Обычный `tar -czf`
> (окно 32КБ) устройство не примет — будет честная ошибка
> `need ...32768`.

## Источники тревог

```text
область:  ubilling (прямо) -> tryvoha (запасной)
юнит:     aiu raw -> ual raw -> область по ubilling (тег ubilling~oblast)
```

- **ubilling** `http://ubilling.net.ua/aerialalerts/` — ~4КБ, только области;
  пауза 700мс между сырыми запросами (лимит ~2 rps). `alertnow` поднимается
  и от тревог в отдельных районах — для юнитов это осознанно грубый
  последний fallback.
- **aiu raw** (alerts.in.ua, до ~64КБ): активная тревога = `location_title`
  из набора цепочки + `finished_at` не задан; `alert_type` не проверяется.
- **ual raw** (ukrainealarm): `regionName` из набора + непустой `activeAlerts`.
- **Сканер `_RawScan`** — байтовая машина состояний: тело в RAM не копится
  (`SCAN_BODY_LIMIT` 256КБ), соединение обрывается на первом совпадении,
  декодирует `\uXXXX`. Имена цепочки в одном наборе: тайтл любого звена
  (громада/город/район/область) активен — регион активен. `ALIASES`
  сводит расхождения имён между источниками.
- **tryvoha** `http://tryvoha.online/api/v1/alerts/{slug}` — с 2026-09
  отдаёт `301 → https` (Cloudflare), а TLS на ESP нет: прямое обращение
  всегда падает. Запасной источник только для областей, юниты в него не ходят.
- **Fallback юнитов**: словарь `PARENT` (130 записей: юнит → район →
  область, сверено с aiu и справочником alerts.in.ua). При отказе обоих
  raw-источников юнит показывает тревогу своей области — точность ниже,
  тег источника на странице честный.
- При отказе всего LED держит последнее состояние, `last_err` виден
  на странице и в `/status`.

## Конфиг (`config.json`, только по Save)

| Ключ | Тип | Дефолт | Описание |
| ---- | --- | ------ | -------- |
| `region` | slug | `odeska` | Регион из 155 (валидируется, чужой → дефолт) |
| `check_interval` | 10–3600 | `60` | Период опроса API, сек |
| `wifi_ssid` / `wifi_pass` | строки | `""` | STA-подключение; смена → авторебут |
| `blink_on_ms` / `blink_off_ms` | мс | `500` | Мигание (правкой файла, в панели нет) |

Санитизация при каждом чтении: неизвестные ключи отбрасываются, интервал
клипается, регион проверяется по `REGIONS`.

## Веб-панель и роуты

Панель на чистом CSS (radio-вкладки): статус-карта + «Регион и проверка»,
«Настройки WiFi», «Обновление прошивки» (там же опасная зона: ребут).
Футер показывает режим сети и IP ссылкой.

| Метод + путь | Что делает |
| ------------ | ---------- |
| `GET /` | Панель (стрим-рендер, 18 токенов) |
| `GET /status` | JSON: `fw/alert/region/source/last_err/ip/log_tail` |
| `POST /save` | Форма настроек → `config.json`, ребут при смене WiFi |
| `POST /reboot` | `machine.reset()` |
| `POST /ota-bundle` | multipart `.tar.gz` → распаковка → `Пакет OK` + ребут |
| `POST /ota-url` | Скачать файл/бандл по URL самому ESP (вызов ручным POST) |
| `POST /upload` | Отключён: одиночная заливка только через USB |

## Скрипты

| Скрипт | Назначение |
| ------ | ---------- |
| `upload.bat f1 f2...` | **Основной путь**: файлы из `src/` по USB (mpremote, COM3) + reset |
| `pack.bat` / `pack.py` | Сборка `firmware.tar.gz`: tar + gzip **wbits=9**, авто-компиляция `.mpy` |
| `build-mpy.bat` | `.py` → `.mpy` отдельно от бандла (нужен mpy-cross 1.28.x: `pip install mpy-cross==1.28.0.post2`) |
| `release.py` / `release.bat` | Релиз `X.Y.Z`: снапшот `releases/X.Y.Z/` (zip + `MANIFEST.txt`, в git не идёт) → тег → GitHub Release с ассетами zip, MANIFEST.txt, firmware.tar.gz |

Для `.bat`: CRLF-переводы строк (LF ломает `goto`/`if`), без скобок в REM.

## Обновление прошивки

- **USB (основной)**: `upload.bat web.mpy version.py` — только изменённые
  файлы + reset. Проверка: `/status` → `fw`. Требует свободного COM-порта
  (отпустить Thonny).
- **OTA (запасной)**: `pack.bat` → форма «Полный архив» → `Пакет OK` →
  ребут кнопкой. Перед записью старые файлы копируются в `/bak` потоково
  по 1 КБ. Если бэкап не удался, в ответе OTA видно `бэкап не удался: …`;
  `config.json` не затирается никогда.
- **Откат (без панели)**: удержать **FLASH** (GPIO0) ~2с после нажатия
  **RST** — `boot.py` восстанавливает файлы из `/bak`. Ответ LED: 5 вспышек
  = откат выполнен, 10 = ошибка или `bak` пуст. Срабатывает и при сломанных
  main/web/шаблоне, пока жив REPL. Запись идёт через стейджинг `x.rbt` +
  rename — корневой файл не остаётся обрезанным.
- **Настройки**: `config.json` пишется только по «Сохранить» и атомарно
  (`config.json.tmp` → rename): при обрыве питания остаётся старый либо
  новый файл, но не полусохранённый.
- **Релиз**: `release.py X.Y.Z` — снапшот и публикация одной командой
  (см. «Скрипты»).

> [!WARNING]
> Держать FLASH при обычном включении (power-on) нельзя — чип уйдёт в режим
> прошивки (download mode). С кнопкой RST это работает, с питанием — нет.
> Запасной путь с ПК: `upload.bat` известных-хороших файлов либо
> `mpremote connect COM3 exec "import ota; ota.rollback()"` + reset.

## Диагностика

| Симптом | Причина → лечение |
| ------- | ----------------- |
| `memory allocation failed, allocating 12965` на `/` | Старый рендер целой страницей → обновиться (стриминг) |
| `ERR: ...301 Moved Permanently` | tryvoha требует https → норма; юниты идут через aiu/ual, последний рубеж — `ubilling~oblast` |
| `Ошибка приема: memory allocation failed` | Старый приём бандла в RAM → обновиться (стрим в файл) |
| `Ошибка пакета: need uzlib/zlib` | Прошивка без `deflate` → обновиться (ветка `deflate`) |
| `Ошибка пакета: ...32768` | Бандл собран не `pack.py` (wbits=15) → пересобрать `pack.bat` |
| `бэкап не удался: x` в ответе OTA | Нет места/ошибка flash при копировании в `/bak` → освободить flash, повторить |
| Панель не грузится, нужен откат | RST → зажать FLASH ~2с до вспышек (5 = ок, 10 = ошибка/`bak` пуст) |
| Кнопка FLASH не сработала | Отпустили раньше ~400мс удержания или вне окна ~2с → повторить |
| Параметры съехали в дефолты после Save | Обрыв питания при записи конфига старыми версиями → обновиться |
| `failed to access COM3` | Порт держит Thonny → Stop/закрыть |
| `.bat` выполняет куски комментариев | LF-переводы или скобки в REM → CRLF, без скобок |
| `/status` молчит, пинг есть | Веб-поток лёг → ребут; REPL-лог через USB |
| Нет ping/DNS при живом WiFi после заливки `.py` | У `.py` приоритет: убрать `.py` с устройства (залить `.mpy`), ребут |

## Железо

- NodeMCU-32S: встроенный синий LED на GPIO2 + внешний параллельно
  (анод → GPIO2, катод → 220–330 Ом → GND). Пин зашит в `hw.py`.
- В простое погашен, при `alert` мигает 500/500 мс.
- Кнопки: **RST** — перезагрузка; **FLASH** (GPIO0) — зажата ≥400мс в окне
  ~2с после старта → откат из `/bak`, затем авто-перезагрузка.

## Тестирование

Тестового раннера в репо нет — проверки гоняются на ПК портируемым Python
со стабами MicroPython (`const`, `uctypes`, `uzlib`/`deflate`, `machine`),
затем импорт настоящих `ota.py` / `web.py` / `alerts.py` / `utarfile.py`:

- `python -m py_compile src/*.py` — синтаксис;
- round-trip бандла (ALLOWED-фильтр, бэкап, `config.json` жив);
- потоковый `backup`/`rollback` (sha-копии, staging `.rbt`), атомарность
  `save()` (упавший `rename` → старый конфиг цел);
- побайтовая эквивалентность стрим-рендера при чанках 7–5000, приём
  multipart 30КБ;
- полнота `PARENT` 130/130 + сверка имён цепочек со справочником
  alerts.in.ua; `_RawScan` на реальных выгрузках aiu/ual (разрезы 1..4096,
  `\uXXXX`, негативы, битый JSON);
- сценарии `check()` со стабами источников.
