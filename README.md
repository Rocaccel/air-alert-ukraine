# ESP Alert v2.0 — светодиод по тревоге в выбранном регионе (без Telegram)

Плата: ESP32-S + MicroPython. Telegram вычищен полностью (v2.0).

## Источники (зашиты, добавлять нельзя)

1. **Ubilling aerialalerts** — `http://ubilling.net.ua/aerialalerts/`, без ключей,
   ~2.5КБ: `{"states": {"Одеська область": {"alertnow": bool}}}`.
2. **Tryvoha** — `http://tryvoha.online/api/v1/alerts/{slug}`, без ключей,
   ~300Б: `{"active": bool, "active_anywhere": bool, ...}`.
Оба по plain HTTP (на ESP нет TLS). Авто-failover ubilling → tryvoha
(районы и города-громады — только tryvoha, ubilling их не знает).
Триггер — готовый bool (слов/каналов/зеркал больше нет).
При отказе обоих LED держит последнее состояние.

## Логика (v2.1)

- Регион выбирается на странице с поиском (поле + datalist, 145 вариантов:
  24 области + м.Київ/Харків/Запоріжжя + все районы). Районы точнее
  (только свой), области чувствительнее (вся область).
- Районы/города-громады идут только через tryvoha (в ubilling их нет) —
  фолбэк это учитывает. Громады-комьюнити не включены (мелкие, список плавает).
- Опрос каждые `check_interval` (по умолч. 60 с). Состояние только в RAM,
  во flash ничего в цикле не пишем (нет износа).

## Железо

- Внешний LED параллельно встроенному: анод → GPIO2 (зашит в `hw.py`, меняется только прошивкой), катод → резистор 220–330 Ом → GND.
- В простое LED погашен, при `alert` мигает 500/500 мс. Встроенный синий на NodeMCU-32S моргает вместе с внешним.
- При старте: 1 вспышка = STA ok, 2 = AP-режим (`ESP32-ALERT`).

## Архитектура

Проверка API — в главном таске; мигание + веб — во вторичном потоке
(стек 6КБ, heartbeat + сторож с рестартом). `ota.py` грузится лениво.

## Прошивка MicroPython

1. Прошить ESP32-S свежим MicroPython (Thonny → Tools → Options → Interpreter).
2. Залить из `src/`: `boot.py, main.py, config_store.py, alerts.py, web.py, ota.py, version.py, hw.py, logbuf.py, template.html, utarfile.py`.
   `utarfile.py` вендорен из micropython-lib (MIT) — OTA-бандл распаковывается
   из коробки, никакого `mip install` на устройстве не нужно.
4. ВАЖНО при переходе с 1.x: удалить `telegram.py` с устройства вручную
   (OTA-пакет его не удаляет; инертный, ни на что не влияет) и один раз
   выбрать регион + Save (старый `config.json` сам санитизируется).

## Заливка файлов (USB — основной, OTA — запасной)

- USB: `upload.bat web.py version.py` — зальёт только перечисленное из `src/` по COM3 (`set ESPPORT=...` для другого порта) + reset. Перед запуском отпустить порт в Thonny. Проверка: `/status` → `fw`.
- OTA (когда USB недоступен): `pack.bat` → `firmware.tar.gz` → форма «Полный архив .tar.gz» → «Пакет OK» → ребут. Формат бандла: gzip **wbits=9** (собирать только `pack.py`; обычный `tar -czf` устройство не примет).
- Важно для агента: `.bat`-файлы хранить в CRLF (LF ломает `goto`/`if`-блоки в cmd) и без скобок в REM-строках.

## WiFi и веб-панель

- Старт: пробует `WIFI_SSID/PASS` 15 с → если неудача поднимает AP `ESP32-ALERT`, страница `http://192.168.4.1/`.
- В рабочем режиме страница по STA-IP (смотреть в роутере или в REPL `STA IP: ...`).
- На странице: регион (select), период 10–3600 с, WiFi, тумблер OTA,
  статус `alert/region/source/last/err/ip`. Без пароля.

## OTA (только публичные ссылки, без одиночного .py)

1. **Всё сразу**: `pack.bat` → `firmware.tar.gz` → форма «Полный архив .tar.gz». Распаковка через `deflate/uzlib+utarfile`, `config.json` не затирается. Проверка наличия `main.py`.
2. **По URL**: только публичный URL. Поле URL + `target` или галка `это .tar.gz пакет`.
3. **Откат**: кнопка «Откат из /bak». Выкл. тумблером OTA.

## Файлы

- `src/*.py` — прошивка, `config_default.json` — дефолты, `pack.bat`/`pack.py` — сборка пакета, `upload.bat` — заливка по USB.
- На ESP создается `config.json` (только по Save) — flash пишется редко.
